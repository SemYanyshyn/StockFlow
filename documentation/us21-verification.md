## Що реально виконано

На macOS ARM64, SDK .NET 8.0.427, PostgreSQL 18.4 (Postgres.app):

```sh
dotnet restore StockFlow.sln
dotnet build StockFlow.sln -c Release --no-restore --disable-build-servers -m:1
dotnet test StockFlow.sln -c Release --no-build --no-restore --disable-build-servers -m:1
bash scripts/Verify-Movements-Isolated.sh
```

Restore успішний; Release — 0 warnings / 0 errors; **356 unit-тестів passed,
0 failed / skipped**. **15 інтеграційних перевірок PostgreSQL passed**:
порожня БД й немає збігів, JOIN/NULL/усі одиниці, сортування, тип, склад,
комбіновані фільтри, кириличний пошук, літеральний injection-рядок / `%`,
межі дня включно з 23:59:59.999999, деталі та реальні login обох ролей.

Окремо створено власний демонстраційний PostgreSQL-кластер і БД
`stockflow_isolated_se8_demo`, застосовано schema/seed і шість локальних fixtures
з різними типами, датами й складами. Їхні дельти узгоджені зі stock в одній
транзакції, min_threshold збережено. Production query service і login обох ролей
перевірені на цих даних: **15 перевірок passed**. Демо-дані та локальна конфігурація
не комітяться: вони залишаються лише в ignored-пакеті `se8-windows.local`.
Робочих БД не торкалися. Нові паролі не створювалися й не комітяться.

Доступного Windows-хоста немає: цей комп'ютер — macOS, зареєстровані UTM-файли
належать Linux-машинам. **Фактичних перевірок Windows/WPF — 0**.
Cross-build та тести ViewModel не замінюють UI-прогін. Відповідно push і PR не виконані.

## Передача та продовження

Самодостатній git bundle містить гілки main, оригінальну SE-8 та кандидат US-21.
Пакет також містить manifest з точними SHA, локальний demo.sql, Start-Demo.ps1,
Use-Demo.ps1 / Stop-Demo.ps1 та інструкції CONTINUE-IN-CODEX.txt.
Демо-SQL захищений точним ім'ям БД і відмовляється працювати з непорожньою
таблицею рухів. Windows setup створює власний кластер на вільному loopback-порту
та задає process-local connection environment, зберігаючи особистий appsettings.json.

На Windows клонувати bundle в НОВУ папку, перевірити SHA кандидата за manifest,
відкрити цю папку в Codex та передати CONTINUE-IN-CODEX.txt. Потрібні Git, SDK
.NET 8 та PostgreSQL 15+ із ICU. Скрипти налаштування Windows підготовлені,
але на macOS не виконувалися; це не видається за Windows-перевірку.

Після restore/build/test запустити саме застосунок:

```powershell
dotnet run --project src/StockFlow.UI/StockFlow.UI.csproj -c Release
```

Увійти `employee` / `EmployeeDemo!2026` (публічний seed лише тестової БД) →
«Накладні»: шість записів. Показати викладачу:

| Дія | Очікуваний результат |
| --- | --- |
| Пошук `нк-204` | Один запис НК-204 |
| Тип «Надходження» | Три записи |
| Склад №2 | Три записи |
| Дата від і до 13.11.2026 | НК-203 і НК-204, без НК-205 |
| Додатково «Надходження» і Склад №2 | Лише НК-203 |
| «Очистити» | Знову шість записів |
| «Переглянути» НК-203 | Постачальник, примітка, кількість/одиниця; редагування немає |
| «Переглянути» НК-204 | Примітка; постачальника немає |
| Пошук без збігу | Українське повідомлення про відсутність результатів |
| Повернення та повторний вибір меню | Список повторно завантажено |

повторити відповідні перевірки на остаточному коміті. Лише потім звичайний push
