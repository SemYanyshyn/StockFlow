Однакова помилка невідомого логіна/пароля; блокування показується тільки після правильного пароля. Паролі не виводяться у повідомлення. Seed і обережне оновлення placeholder-паролів для наявної БД.

Сервіс захищає всі операції, себе й останнього активного Адміна; за наявності рухів пропонує блокування, додатково обробляє FK. Після зміни власної ролі оновлюються контекст, меню й CanManage.

Потрібні Windows, .NET 8 та PostgreSQL 15+ із ICU. Для чистої БД: 01_schema.sql, потім 02_seed.sql. Для наявної БД: резервна копія; 03_update_demo_passwords.sql лише якщо потрібні старі demo-placeholder-акаунти; 04_categories_case_insensitive.sql для індексу категорій. Конфігураційний CurrentRole більше не перемикає роль. Повні інструкції — у README.

## Межі перевірки

Computer Use тричі, включно з повторною ініціалізацією JS, повернув `Computer Use native pipe is unavailable: failed to connect native pipe: The system cannot find the file specified. (os error 2)`. Тому ручні кліки, фізичне введення у PasswordBox, реальне натискання Yes/No у MessageBox та закриття вікна входу вручну не перевірені. Програмні WPF-перевірки й огляд коду не позначаються як ручні. Протокол App явно тримає OnExplicitShutdown до успіху входу, викликає Shutdown при закритті LoginView і перемикається на OnMainWindowClose для головного вікна; ручне підтвердження цього життєвого циклу залишається потрібним.

ICU є вимогою міграції; без ICU вона завершується помилкою. Коротке табличне блокування users серіалізує керування користувачами; це свідомий вибір для невеликого настільного застосунку. PostgreSQL 15 та інші версії ОС окремо не перевірялися. Робочі дані, віддалені GitHub-права й командні модулі за межами інтеграції не змінювалися.
