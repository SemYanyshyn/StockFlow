# MA-10: керування користувачами та безпечні оновлення БД

Base: feature/auth-login (після її merge — main). Branch: feature/users-management.
Related issues: #24 (US-11), #167 (US-27), #168 (US-28), #169 (US-29), #170 (US-30).

Адмін отримує список користувачів, пошук за логіном/ПІБ, фільтр ролі, створення, редагування ПІБ/ролі, блокування/розблокування й видалення з підтвердженням. Логін незмінний; збережено чинну регістрозалежну UNIQUE(username), а паролі зберігаються лише як PBKDF2-хеші. Список і контекст сесії не видають хешів. Employee не може викликати захищені операції навіть напряму через сервіс.

UserService володіє транзакцією, яка через DataAccess бере SHARE ROW EXCLUSIVE на users до читання перевірок. Перевірка останнього активного Адміна та зміна відбуваються разом, включно з повторною перевіркою ролі виконавця з БД. Заборонено блокувати/видаляти себе. Для користувача з рухами пропонується блокування; FK 23503 — додатковий захист. Після зміни власної ролі оновлюються контекст, меню та CanManage.

Для категорій додано ICU-індекс у чисту схему й окрему міграцію 04 для наявної БД. Конфлікти повідомляються з ID/назвами без видалення чи об’єднання. README описує запуск, демонстраційні паролі, міграції, правила ідентичності та поточний стан. Збережено реєстрації модулів команди.

Перевірено: restore; Release build, 0 warnings/errors; 328 unit-тестів без PostgreSQL; 32 реальні PostgreSQL-перевірки, зокрема конкурентне пониження ролі/блокування/видалення з двох підключень; 27 програмних Windows/WPF-перевірок і рендери; сценарій оновлення legacy-БД із збереженням історії та конфліктами категорій. Перевірка кліками не виконана через недоступний native pipe Computer Use; подробиці — у ma8-ma10-report.md.
